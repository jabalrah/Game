=====================================================================
 GAME 2D MULTIPLAYER - PANDUAN LENGKAP
=====================================================================

ISI PROYEK
  index.html, game.js, assets/   -> game (dihosting di GitHub Pages)
  server/                        -> server multiplayer (dihosting di Render)

KONTROL
  WASD / tombol panah   bergerak (di HP: tombol di layar)
  Enter                 mulai mengetik chat, Enter lagi untuk kirim, Esc batal
  Tombol di kanan atas  Musik, Efek langkah, Ganti nama, Kostum

---------------------------------------------------------------------
 A. MENCOBA DI KOMPUTER SENDIRI (disarankan sebelum online)
---------------------------------------------------------------------
Butuh: Node.js (nodejs.org, pilih versi LTS) dan Python (untuk server web lokal).

1. Jalankan SERVER. Buka terminal di folder "server", lalu ketik:
       npm install
       npm start
   Muncul tulisan "Server berjalan di port 3000". Biarkan terminal ini terbuka.

2. Jalankan GAME. Buka terminal BARU di folder utama (yang berisi index.html):
       python -m http.server 8000
   (di Mac/Linux kadang: python3 -m http.server 8000)

3. Buka http://localhost:8000 di browser. Isi nama, lalu Mulai Main.
   Di kiri atas harus tertulis "Online: 1 pemain".

4. Untuk mencoba dua pemain: buka http://localhost:8000 lagi di JENDELA INCOGNITO
   (atau browser lain) supaya bisa memakai nama berbeda. Gerakkan satu karakter,
   dan lihat di jendela lainnya.
   Catatan: dua tab biasa di browser yang sama berbagi nama yang tersimpan.

Jika di kiri atas tertulis "Tidak terhubung ke server", berarti langkah 1 belum
berjalan, atau alamat di game.js (serverUrl) tidak cocok dengan port server.

---------------------------------------------------------------------
 B. MEMASANG ONLINE (gratis): game di GitHub Pages + server di Render
---------------------------------------------------------------------
Langkah 1 - Unggah ke GitHub
  1. Buat akun di github.com, lalu buat repository baru (Public), misalnya "game-saya".
  2. Unggah SEMUA isi folder ini: index.html, game.js, assets, folder server
     (kecuali node_modules kalau ada). Lewat "Add file" > "Upload files".
     index.html harus berada di paling atas repository.

Langkah 2 - Pasang SERVER di Render
  1. Buka render.com, daftar dengan akun GitHub.
  2. Klik "New +" > "Web Service", lalu pilih repository "game-saya".
  3. Isi pengaturan:
       Root Directory   : server
       Runtime          : Node
       Build Command    : npm install
       Start Command    : npm start
       Instance Type    : Free
  4. Buka bagian "Environment Variables", tambahkan:
       ALLOWED_ORIGINS = https://NAMAAKUN.github.io
     (ganti NAMAAKUN dengan nama akun GitHub Anda; tanpa garis miring di akhir,
      tanpa nama repository). Ini mencegah situs lain memakai server Anda.
  5. Klik "Create Web Service" dan tunggu sampai berstatus "Live".
  6. Salin alamatnya di bagian atas halaman, bentuknya
       https://nama-game.onrender.com

Langkah 3 - Sambungkan game ke server
  1. Di GitHub, buka file game.js, klik ikon pensil (Edit).
  2. Cari baris serverUrl di bagian CONFIG, ubah menjadi alamat Render dengan
     awalan wss:// (BUKAN https://):
       serverUrl: "wss://nama-game.onrender.com",
  3. Klik "Commit changes".

Langkah 4 - Aktifkan GitHub Pages
  1. Repository > Settings > Pages.
  2. Source: "Deploy from a branch", Branch: main, folder: / (root), lalu Save.
  3. Tunggu 1-2 menit. Alamat game: https://NAMAAKUN.github.io/game-saya/
  4. Bagikan alamat itu. Siapa pun yang membukanya akan bertemu di dunia yang sama.

PERLU DIKETAHUI TENTANG PAKET GRATIS RENDER
  - Server gratis akan "tertidur" jika lama tidak ada pengunjung. Pemain pertama
    setelah itu menunggu sekitar satu menit sampai server bangun. Selama itu status
    tertulis "Menghubungkan..." lalu tersambung sendiri. Pemain berikutnya langsung cepat.
  - Batas dan syarat paket gratis bisa berubah. Cek halaman harga Render sebelum
    mengandalkannya untuk game yang ramai.
  - Server menyimpan data di memori. Jika server dimulai ulang, semua pemain
    tersambung ulang otomatis, dan posisi mereka dimulai lagi dari posisi terakhir di layar masing-masing.

---------------------------------------------------------------------
 C. PENGATURAN SERVER (Environment Variables di Render, atau saat npm start)
---------------------------------------------------------------------
  ALLOWED_ORIGINS  Alamat web yang boleh terhubung, pisahkan dengan koma.
                   Kosong = semua boleh (cocok untuk tes lokal).
                   Contoh: https://akun.github.io,http://localhost:8000
  MAX_PLAYERS      Batas pemain bersamaan (bawaan 50).
  MAX_PER_IP       Batas koneksi dari satu jaringan (bawaan 10).
  BLOCKED_WORDS    Kata yang disensor di chat dan ditolak di nama, pisahkan dengan koma.
                   Contoh: kata1,kata2,kata3
  WS_DEFLATE       Kompresi WebSocket, bawaan AKTIF (hemat upload ~65%, CPU naik). Isi 0 untuk mematikan
                   (disarankan jika server di hosting dengan CPU kecil).
  NEAR_RADIUS      Radius "dekat" (piksel) jika klien tidak mengirim ukuran layar (bawaan 1500).
  CROWD_AT         Jumlah pemain di atas ini: posisi dekat dikirim 10x/detik, bukan 20x (bawaan 24).
  BOARD_SIZE       Jumlah baris papan skor (bawaan 10). Skor = jumlah kupu-kupu yang ditangkap selama online.
  CHICKEN_COUNT    Jumlah ayam di server (bawaan 0 = mati, karena game belum memuat ayam.js).
  WORLD_WIDTH, WORLD_HEIGHT   Ukuran peta (bawaan 4096 x 4096). Ukuran dari server
                   otomatis dipakai oleh game.

Pemeriksaan otomatis di server:
  - Nama 2-16 huruf; karakter kontrol dan karakter pembalik arah teks dibuang.
  - Chat maksimal 80 huruf, jeda minimal 0,7 detik antar pesan.
  - Kostum harus berformat benar (id huruf kecil, warna #rrggbb).
  - Posisi dibatasi di dalam peta; pesan terlalu besar atau terlalu sering ditolak.

---------------------------------------------------------------------
 D. MENGUBAH GAME
---------------------------------------------------------------------
Semua pengaturan ada di bagian CONFIG pada game.js (ukuran peta, kecepatan, volume,
durasi chat, serverUrl, dan lain-lain).

Karakter: pemain memilih satu KARAKTER (badan + baju + celana + sepatu sudah menyatu).
Daftar karakter dibaca OTOMATIS dari folder assets/body/. Tidak perlu mengedit game.js.

Menambah karakter baru:
  1. Buat folder  assets/body/<nama>/        contoh: assets/body/baju-merah/
  2. Isi dengan   1.png ... 6.png               (6 frame animasi JALAN, wajib)
                   idle1.png ... idle3.png       (3 frame animasi DIAM/idle, boleh tidak ada)
  3. Simpan, lalu muat ulang game (Ctrl+F5). Karakter baru muncul di menu Kostum.
  Aturan:
   - Ukuran kanvas semua gambar SAMA, latar transparan (bawaan 128 x 128).
   - Frame 1 = pose diam.
   - Nama folder: huruf kecil, angka, - dan _ saja, maksimal 24 karakter.
   - Folder yang gambarnya tidak lengkap atau namanya tidak sesuai dilewati otomatis;
     alasannya tertulis di Console browser (F12).
  Jumlah frame diatur di game.js: CONFIG.frameCount (jalan, sekarang 6),
  CONFIG.idleFrameCount (idle, sekarang 3), dan CONFIG.idleFps (kecepatan idle).
  Animasi idle: diputar berulang saat karakter diam. Jika karakter tidak punya idle1-idle3,
  game memakai frame jalan pertama sebagai gambar diam. Jika idle tidak lengkap (misalnya
  hanya idle1.png), animasi idle itu tidak dipakai dan ada peringatan di Console.

Cara game membaca daftar folder:
  - Di komputer sendiri (localhost): dari daftar folder server web.
  - Di GitHub Pages: dari API GitHub (dibatasi 60 permintaan per jam per alamat IP; hasilnya
    disimpan di browser selama 2 menit). Jika gagal, memakai assets/body/daftar.json.
  - assets/body/daftar.json dibuat otomatis oleh tes-lokal.ps1 dan mulai-server.ps1.
    Kirim file ini ke GitHub bersama folder karakter baru (git add -A).
  - Jika semuanya gagal, game memakai daftar bawaan CONFIG.fallbackBodies.

Menambah karakter di GitHub:  git add -A  ->  git commit  ->  git push
(tunggu 1-2 menit sampai GitHub Pages selesai, lalu Ctrl+F5).

Gambar lain:
  assets/background.png  latar. backgroundMode di CONFIG (bawaan "auto"):
    - file latar sebesar peta (mis. 4096 x 4096) -> dipakai SATU file penuh, tidak diulang,
      dan ukuran peta otomatis mengikuti file itu.
    - file latar lebih kecil (mis. 1024 x 1024) -> diulang seperti ubin.
    Paksa dengan "map" (satu file penuh), "tile" (diulang), atau "stretch" (diregangkan).
  assets/layer.png  (OPSIONAL) layer rintangan di atas latar. PNG transparan.
    Bagian yang TERISI gambar = tembok (pemain tidak bisa lewat), bagian BOLONG = bisa dilewati.
    layerMode "map" (bawaan): SATU file menutupi seluruh peta, contoh latar 1024 x 4 = 4096 x 4096.
      Ukuran peta otomatis = ukuran layer. Kalau online, isi WORLD_WIDTH dan WORLD_HEIGHT di server
      dengan ukuran yang sama (bawaan server sudah 4096). Mode lain: "tile" (diulang), "stretch".
    Kotak tabrak ada di kaki karakter; diatur lewat layerHitWidth/layerHitHeight di CONFIG.
    Isi layerDebug: true untuk melihat kotak tabraknya.
    Game harus dibuka lewat server/localhost (bukan klik dua kali index.html) agar tabrakan terbaca.
    Buka F12 (console) untuk melihat pesan status layer.

Suara (assets/audio/): bgm.wav (musik latar), step1.wav dan step2.wav (langkah).
  Ganti dengan file Anda dan sesuaikan nama di CONFIG jika berbeda. Untuk game yang sudah
  online, ubah ke .ogg atau .mp3 agar ukurannya kecil. Pakai suara yang Anda punya haknya.

Jika gambar asli menghadap KIRI, ubah spriteFacesRight menjadi false.

CATATAN GITHUB PAGES
  - Nama file dan folder membedakan huruf besar/kecil. Pakai huruf kecil semua.
  - Setelah mengubah file, tekan Ctrl+F5 agar browser memuat versi baru.

---------------------------------------------------------------------
 E. BATASAN YANG PERLU ANDA TAHU
---------------------------------------------------------------------
  - Server mempercayai posisi yang dikirim pemain (hanya dibatasi di dalam peta).
    Pemain yang paham teknis bisa curang, misalnya berpindah tempat seketika. Untuk game
    santai ini tidak masalah, tapi jangan dipakai untuk hal yang menyangkut persaingan.
  - Belum ada tabrakan antar pemain, akun, atau penyimpanan permanen di server.
  - Filter kata hanya sebatas daftar yang Anda isi di BLOCKED_WORDS. Untuk game publik
    yang ramai, tetap perlu pemantauan.
  - Satu server memadai untuk puluhan pemain. Untuk ratusan pemain perlu desain yang berbeda.

---------------------------------------------------------------------
 E. NPC & KUPU-KUPU BERSAMA (dihitung di server)
---------------------------------------------------------------------
Saat online, NPC, komentar NPC, dan kupu-kupu dihitung di SERVER (server/dunia.js),
jadi semua pemain melihat yang sama. Siapa yang menangkap kupu-kupu lebih dulu yang
mendapatkannya. Jumlah tangkapan tetap disimpan di browser masing-masing.

Yang perlu diperhatikan:
  - Jalankan "npm install" lagi di folder server (ada tambahan paket pngjs).
  - Folder server/ berisi dua SALINAN file game:
        server/layer.png         salinan assets/layer.png   (rintangan untuk NPC)
        server/npc-komentar.js   salinan npc-komentar.js    (kalimat & nama NPC)
    Kalau Anda mengubah salah satunya di game, salin juga ke folder server/ lalu
    jalankan ulang server.
  - Pengaturan gerak NPC (NPC_CONFIG di npc.js) dan kupu-kupu (KUPU_CONFIG di kupu.js)
    ada duplikatnya di bagian atas server/dunia.js. Ubah di dua tempat supaya sama.
  - Tanpa server (serverUrl kosong), NPC & kupu-kupu dihitung di browser seperti biasa.
    Kalau server sedang tidak tersambung, NPC & kupu-kupu menghilang sampai tersambung lagi.

---------------------------------------------------------------------
